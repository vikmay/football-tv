# Football TV — Codebase Overview

## Summary

A zero-backend, static football schedule + World Cup standings viewer, deployed via GitHub Pages. Data is collected from Flashscore (scraped/parsed), UPL's official site, and worldcupstats.football via a Node.js script (`parse.js`), stored in a JSON file (`matches.json`), and rendered client-side by `index.html`. It serves Ukrainian football fans with a focus on Ukrainian Premier League (UPL), Champions League, and the 2026 World Cup.

## Architecture

Single-page static web app:

- **Frontend**: `index.html` — vanilla JS that fetches `matches.json` and renders it as an HTML schedule + standings tables.
- **Data layer**: `matches.json` — generated JSON with match data keyed by league name; also holds a `"Таблиця ЧС 2026"` key with group standing rows.
- **Data fetcher**: `parse.js` — Node.js script (run in GitHub Actions or locally) that scrapes multiple sources, deduplicates, normalizes team names, and writes `matches.json`.
- **Cache control**: `matches.meta.json` — TTL metadata to avoid over-fetching.
- **CI**: `.github/workflows/update.yml` — GitHub Actions workflow that runs `parse.js` on a schedule.

There is no framework, no build step, no bundler. The HTML file contains all CSS (inline `<style>`) and JS (inline `<script>`).

## Key Features in the Frontend

### Match Schedule Rendering

- Fetches `matches.json`, deduplicates matches by identity, groups by date (Kyiv timezone)
- Renders each match as a card: league label, teams, score or time
- Scrolls to today's date on load
- Supports live/dynamic updating via cache-busting `?cache=` param

### World Cup Group Standings

- Reads `matches.json["Таблиця ЧС 2026"]` — an object keyed by group letter (A-L), each with an array of team rows
- Each row: `position`, `teamName`, `played`, `wins`, `draws`, `losses`, `goalsFor`, `goalsAgainst`, `goalDifference`, `points`
- Renders 12 group tables (A through L) with headings like "Таблиця ЧС 2026 — Група A"
- Falls back to fetching from `worldcupstats.football` if the local JSON key is missing

### Team Name Normalization

- Extensive mapping for team names: UPL team names (English → Ukrainian), World Cup team names (English → Ukrainian), club aliases
- Handles Flashscore's inconsistent team naming (short forms, hyphen-split names)

## Non-Obvious Behaviors & Design Decisions

### 1. Matches.json doubles as a schedule AND standings store

The `"Таблиця ЧС 2026"` key lives inside `matches.json` alongside league match arrays. This is an unusual hybrid structure — standings data is generated by `parse.js` (from worldcupstats.football scraping) and merged into the same JSON file for single-request loading.

### 2. Deduplication is complex and layered

There are multiple deduplication passes:

- `dedupeMatchesByPairKeepLatestDate` — keeps the latest date for the same team pair
- `dedupeMatchesByIdentity` — filters out duplicates by identity key
- `dedupeScheduleSections` — league-specific dedup with special handling for World Cup (ignoring time for identity) and UPL (sorted home/away)
- The frontend also deduplicates by identity on load, preferring finished matches with real scores

### 3. Cache TTL is dynamic

`parse.js` adjusts refresh TTL based on data freshness:

- 120 min default
- 10 min if there are matches today/tomorrow
- 5 min if there are recently finished matches
- Force refresh via `--force` flag

### 4. Team name normalization is extensive but fragile

There are THREE separate team name mapping systems:

- `uplTeamNames` (English → Ukrainian, in parse.js)
- `worldCupTeamNames` (English → Ukrainian, in both parse.js and index.html — duplicated)
- `flashscoreClubAliases` (lowercase → normalized, in parse.js for dedup lookup)

The duplication between `parse.js` and `index.html` for `worldCupTeamNames` is a maintenance risk — both must be kept in sync.

### 5. Flashscore parsing uses regex on encoded feed data

`parseFlashscoreCupFeedData()` parses Flashscore's proprietary `~AA÷...¬...÷...` format with regex. This is fragile and depends on the exact encoding scheme Flashscore uses.

### 6. World Cup 2026 has 12 groups (A-L)

The code iterates `["A", "B", "C", "D", "E", "F", "G", "H", "I", "J", "K", "L"]` — 12 groups, which matches the expanded 48-team format.

### 7. No UPL standings rendering exists

Despite `"Таблиця УПЛ"` appearing in `sectionOrder` in `dedupeScheduleSections()`, there is NO actual UPL standings rendering in the frontend. The key existed in `parse.js` processing but the frontend only renders WC standings.

## What Needs to Change (Task Analysis)

The user wants two things, referencing the Flashscore WC standings page:

### A. "Рейтинг команд що посіли 3-є місце" — Ranking of 3rd-place teams

In the 2026 World Cup (48 teams, 12 groups), the top 2 from each group (24 teams) + the 8 best 3rd-placed teams advance. Flashscore shows a separate "3rd place ranking" table that ranks the 12 third-place teams by points, GD, goals scored, etc.

This requires:

1. A new rendering function `renderWorldCupThirdPlaceRanking(rows)` that collects the 3rd-place team from each group, sorts them by standard tiebreakers (points → GD → goalsFor), and displays them
2. New CSS for the ranking table
3. Positioning it above or below the group tables

### B. "Виділяти кольором місця в таблицях" — Color highlights for positions

Like Flashscore, color-code:

- **Green/blue**: Top 2 (qualification positions) — advance to Round of 32
- **Orange/yellow**: 3rd place (potential qualification as best 3rd)
- **Red**: 4th place (eliminated)

This requires:

1. CSS classes for position-based coloring
2. Logic in `renderWorldCupGroupStandingsSection()` to assign the right class to each row based on position and the 3rd-place ranking
3. A color legend/note at the bottom

### Data Flow for the New Features

The `matches.json["Таблиця ЧС 2026"]` already contains all 12 groups with `position` fields. The frontend can:

1. Compute the 3rd-place ranking from the existing data
2. Apply CSS classes based on position (1-4) in each group
3. For 3rd-place teams, a second pass determines which advance (top 8 by points → GD → goals)
